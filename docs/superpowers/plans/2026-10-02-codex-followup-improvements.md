### Compatibility and rollout

- No new dependencies, storage migrations, provider adapter, primary UI surface, or capability activation path were introduced.
- Skill ranking is callable only through the explicit offline/evaluation function and script. It is not connected to automatic runtime selection.
- `chatContextBudgetVisibilityV1Enabled` is absent/false by default. Its optional config/env/settings plumbing preserves explicit false and existing stored values through unrelated patches. No operator configuration was changed. The estimate is computed only for a successfully executed `session.status` request after normal policy and capability enforcement.
- `chatAsyncClarificationV1Enabled` is absent/false by default, including `GOATCITADEL_FEATURE_CHAT_ASYNC_CLARIFICATION_V1_ENABLED`. Config, stored settings, dashboard patch validation, and client API types carry it without erasing explicit false. The tool remains inspectable but is excluded from the callable catalog and model schema while disabled. Executor and issuance checks also enforce the flag. Rollback is disabling this flag; required input and approval paths retain their existing behavior.
- Async clarification is restricted to top-level interactive durable Chat and ordinary text. It is excluded from child, scheduled, and heartbeat tool schemas. The existing canonical write fence verifies the executor lease before and after issuance/projection, while storage rechecks admission, incarnation, workspace, session, turn, run, revision, generation, request hashes, actor, active lease, and run-version CAS. No in-memory steer queue is used.
- One unanswered, unexpired optional question is allowed at a time, with at most 16 questions per turn. Titles are bounded to 100 characters, questions to 1,000, and replies to 4,000. Server-issued prompts expire after 15 minutes. Replies retain their exact prompt and operator identity plus a material hash in the durable payload; altered replay, duplicates, stale/foreign scope, cancellation, expiry, and lease loss fail closed. Identical replay after later terminal progress returns the existing receipt without executing again.
- Answers enter the next model boundary as ordinary clarification context, including recovered runs and the separate final synthesis path. Injection is deduplicated within the active loop. This does not create grants or approvals. A reply arriving after the last available model boundary may be saved without affecting the answer; the UI says it can be used at the next step while the turn is active. It does not promise extra unbounded provider work.
- Budget estimates are not reported token usage, a calibrated tokenizer result, a quota promise, or execution authority. Provider-added context remains outside the estimate. Missing route/limit/output-reserve information yields unknown remaining capacity.
- Shell classification remains subordinate to configured patterns, the existing risky-command approval setting, deny-wins policy, grants, path jails, and executor checks. Empty configured risk policy retains its previous behavior. Unknown Windows constructs may now require review.
- Compaction keeps its existing persistence and model-message shape. Provenance-aware source hashes invalidate old summary reuse without a schema change; ordinary fallback remains verbatim context if a window cannot be safely rebuilt. Derived summaries never create original operator provenance or authorization records.
- Windows/PowerShell testing used repository commands and temporary verification fixtures. No user data, credentials, installed payloads, or pre-existing servers were deliberately modified or stopped.
