## Current Quality implementation

The cockpit now reads the existing installation-wide bounded snapshot and renders Gates, Evaluations and Design with exact owner IDs, explicit source availability, warnings, blockers and recorded next actions. The selected prompt-pack report must match the snapshot's pack ID, content hash and update timestamp; the snapshot's `generatedAt` also invalidates report evidence when scores change without a definition edit. Both clipboard exports use the existing read-only APIs; success requires the exact returned content to reach the clipboard. Unavailable metrics remain unavailable, and a failed snapshot refresh withholds the older success projection. The panels reuse the existing status derivation and API clients; no runtime owner was duplicated.

The 755-line classic page uses `useQualityDashboardSnapshot`, `useQualityPromptPackEvidence`, `useQualityEvidenceClipboard`, `QualityEvidenceExportsPanel` and the guarded `useBuiltinPromptPackImport`/`BuiltinPromptPackImportConfirmation` action. Native Quality keeps its query-backed snapshot/detail presentation and shares the clipboard and import owners. This is shared mutation/export lifecycle with separate presentation loading, not a claim that both shells use one snapshot hook.

Focused UI tests cover partial-source failure, exact selection, removed selection, prompt-pack revision drift, refresh failure, clipboard failure/concurrency and unmount during export. The matching-Gateway desktop/phone helper seeds only disposable owner records, compares selected evidence and exact clipboard receipts, and asserts that browser inspection/exports cause no API mutations. Earlier execution results remain checkpoint evidence; this documentation pass did not rerun that helper. Root owns integrated build and browser verification.

### Legacy import finding and implemented guarded replacement

The earlier proposed client-only preflight in item 3 was insufficient to make first import safe under concurrency. The preserved legacy `POST /api/v1/prompt-packs/builtins/:packKey/import` accepts a fixed pack key without a create-only or expected-revision precondition. Without guarded options, [PromptPackService.importBuiltinPromptPack](../apps/gateway/src/services/prompt-pack-service.ts) still imports through `replacePackTests`. Another operator can import or edit the fixed-key pack between client preflight and replacement. The advertisement at the initial audit lacked a reviewed definition revision. A browser pending/unknown lock cannot prevent another caller's write during that interval.

The implemented `POST /api/v1/prompt-packs/builtins/:packKey/import-if-absent` requires the owner-advertised `expectedDefinitionRevision`, derived from the exact prepared definition. `createPackWithTestsIfAbsent` admits the fixed key with `INSERT ... ON CONFLICT ... DO NOTHING` and builds the pack/test receipt inside the same SQLite/PostgreSQL transaction. An occupied key conflicts without deleting or replacing tests. Both Quality presentations share exact advertisement review, receipt plus independent report readback and retained unknown-outcome handling. Unsupported older Gateway advertisements withhold first import. This imports definitions only; it runs no evaluation and does not convert a later occupied-key conflict into proof that an earlier unknown request succeeded.
