# HX-402 Journey Producer Integration Packet

Date: 2026-07-13

Status: **PARTIAL / HOLD**

Scope: Producer design only. This packet does not authorize edits to the runtime owners named below.

## Current truth

The Journey read model, immutable event repository, Gateway route, shared API client, and read-only Library page exist. The page is intentionally labeled experimental because the canonical producer matrix is not complete.

The HX-401 skill-learning transaction in `apps/gateway/src/services/skill-learning-service.ts` writes its evidence, candidate, proposal, and Journey records together. Its correction evidence, inactive candidate, and review-only proposal events now explicitly declare `sourceRequired: true` and `approvalRequired: false`; clean records therefore contribute evidence-only truth without gaining callability or memory authority. Standard and expiry-driven approval resolution writes a content-free, source-linked Journey event in the same immediate transaction as the canonical approval event and effect enqueue. The canonical approval-effect repository now wraps every completed/skipped/failed transition and its content-free Journey event in one nested-safe database transaction. Approvals without valid workspace linkage remain unprojected rather than being assigned a default or global scope. HX-413 lifecycle settlements also emit exact approval/source-bound Journey records. The remaining producer matrix is still incomplete.

The Journey page is evidence-only. It cannot promote a skill, write memory, resolve an approval, install an import, or mutate lifecycle state. Clean evidence remains `evidence_only`; incomplete recurrence scans and any blocked recurrence observation force a blocked contribution.

## Producer invariants

Every producer tranche must preserve all of these rules:

1. Declare both `provenance.sourceRequired` and `provenance.approvalRequired`. Missing declarations fail closed; action-name inference is forbidden.
2. Use a canonical source record that already exists independently of the Journey event. A candidate or evaluation reference can be supporting evidence, but does not by itself satisfy canonical source linkage.
3. Use a real approval ID when approval is required. Confirmation booleans, actor labels, correction action IDs, and an original approval inherited by a later independent mutation are not substitutes.
4. Insert the Journey event in the same database transaction as the canonical mutation and its source history record. If filesystem publication is involved, use an immutable staged candidate/snapshot plus a recoverable settlement protocol; do not claim cross-resource atomicity.
5. Derive the Journey idempotency key from the canonical source identity and action. Retries must replay the same immutable bytes or conflict.
6. Preserve the owner record's actual workspace, session, turn, actor, and approval linkage. Missing scope must stay missing or block the producer; it must not default silently.
7. Keep `summary` and `provenance` bounded and content-free. Store hashes and durable references, not prompt, message, memory, correction, skill, or tool payload text.
8. Candidate creation, evidence capture, proposal creation, and import review remain non-callable. Journey ingestion never activates or promotes them.

## Recommended implementation tranches

1. **Freeze requirement semantics — complete.** Evidence-only correction capture and inactive candidate/proposal staging require canonical source evidence but no approval; the existing HX-401 producer declares both booleans without changing its non-callable behavior.
2. **Approval authority first — complete.** `approval_lifecycle` commits with the canonical resolved event, and the repository-level terminal seam commits `approval_effect_lifecycle` with completed/skipped/failed effect state. Both producers are content-free and transactionally coupled.
3. **Memory history producers.** Start with memory item and structured-memory paths that already have history tables. Return the history ID, propagate a real approval ID, and make mutation + history + Journey atomic. Hold memory-learning/session promotion until an immutable history owner exists.
4. **Skill aggregate lifecycle.** Extend skill-state and capability candidate CAS transactions with canonical lifecycle events, actor/scope, real approvals, and Journey records. Keep proposal and candidate creation review-only and inactive.
5. **HX-413 import/update adoption.** Use immutable upstream snapshots for version/audit/permission/content identity, stage inactive candidates, block same-version byte changes and audit downgrades, and make rollback/revoke inspectable.
6. **Improvement activation recovery.** Eliminate the post-commit audit gap with an in-transaction signal/Journey write or durable outbox plus bounded reconciliation/backfill.
7. **Coverage and release gate.** Add producer contract tests, SQLite/Postgres parity tests if a schema change is approved, crash-point recovery tests, exact workspace isolation tests, and a browser proof. Remove the experimental label only after every matrix row is either shipped or explicitly excluded by frozen product policy.

## Minimum producer contract test

Each owner must prove:

- the domain mutation, canonical source record, and Journey event commit or roll back together;
- duplicate delivery returns identical immutable Journey bytes;
- conflicting replay fails;
- `sourceRequired` and `approvalRequired` are both present;
- required source and approval IDs resolve in the same workspace;
- missing/foreign/quarantined/conflicting evidence stays visible but blocked;
- same-session repeats do not satisfy distinct-session recurrence;
- any blocked recurrence observation and an incomplete bounded scan block trust contribution;
- no producer or Journey read path directly promotes memory, a skill, a candidate, or an import;
- the operator-only Journey route rejects unknown filter keys, requires exact workspace scope, and returns `Cache-Control: no-store` plus `Pragma: no-cache`.

## Ship decision

HX-402 remains **PARTIAL / HOLD**. The current slice is safe as an experimental, read-only evidence projection. Approval resolution and effect settlement are now canonical and transactionally coupled, but the timeline is not yet release-bearing because memory, skill state, legacy imports, direct capability lifecycle, improvement rollback/revoke, and HX-413 upstream admission do not all emit canonical events with explicit source/approval requirements.
